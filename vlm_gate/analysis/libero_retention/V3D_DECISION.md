# libero 문항 v3d 확정 (2026-09-17)

`prompts/libero_v3d_*`. 380타일 프로브 `analysis/ratio_prompt/lb_v3d.jsonl`.

## 무엇을 바꿨나

**포맷을 네 벤치마크 공통 골격에 맞췄다** (robocasa v22 · human_data v3 와 동일):

    You are judging ... (가이던스)
    카메라 뷰 N개 설명
    The robot was told: {지시문}
    MEASURED FROM THE PLANNED MOTION over the chunk ahead (...): {계산 사실}
    등급 서술 + 척도 + 문항

v3c 는 가이던스·문항이 `analysis/_evolver/_libero/` 에 흩어져 있었고 VIEW 는 프로브
스크립트에 하드코딩돼 있었다. 그래서 같은 VIEW 문장이 robocasa 로 글자까지 넘어가
있었다(robocasa 에는 삽입 태스크가 없는데 `fine-insertion instant` 를 찾으라고 했다).
v3d 는 `scripts/libero_v3d_checks.py` 하나가 GUIDANCE·VIEW·SCALE·ASK·SIGN·WEIGHT·
NAME 을 다 들고 있다.

**내용은 두 군데.** 둘 다 기록에 이미 결함으로 적혀 있었다.

1. **A 와 C 가 서로를 상쇄했다.** `V2_DIAGNOSIS.md` 가 "둘 다 해제에서 최고인데
   부호가 반대다" 라고 적어 뒀는데 v3c 까지 안 고쳐졌다(`score_v3c.txt`: A 해제 3.56
   감점 · C 해제 2.91 가점). 같은 축(목적지가 좁으냐 넉넉하냐)을 문항 둘로 쪼개 부호를
   반대로 주면 서로를 지운다. **하나로 합쳤다**(A ROOMY_TARGET, 가점).
   human_data 에서 같은 병합이 좁은 컵과 넓은 접시를 1.19 대 4.28 로 갈랐다.
2. **가이던스 4문단이 아무 문항도 안 묻는 성질을 통째로 설명했다** -- "트인 접근 vs
   끼어든 접근". 그걸 묻던 v2 의 B 가 v3b 에서 "파지 순간" 으로 재조준되며 사라졌다.
   그런데 그것이 libero 에서 **실측으로 값이 묶인 위험**이다(사다리 최고 계단 2.4 아래로
   측정된 여섯이 전부 파지·밀기: grasp_between/confined 1.667 · grasp_stacked 1.819 ·
   grasp_handle 2.00 · push_close 2.03 · grasp_open 2.26). 문항으로 되살렸다
   (C THREADED_PICK, 감점). 그리고 D 를 "이미 놓여 있는가" 에서 **"손이 이미 벌어졌는가"**
   로 다시 썼다 -- human_data 에서 전자가 16스텝 창 때문에 내려놓는 중에도 부분 참이
   되어 위험 문항을 상쇄했다.

## C 와 E 의 낮은 비율은 죽은 것이 아니다 -- 진단 규칙을 고친다

처음에 C(2.9%)와 E(5.3%)를 `V2_DIAGNOSIS` 의 "4등급 이상 0~5% 면 죽은 문항" 규칙으로
죽었다고 판정하고 지우려 했다. **발동이 어디에 몰려 있는지를 안 봤다.**

    C THREADED_PICK
      '~위에 얹힌 것을 집어라' 태스크 (17청크)   4등급이상 41.2%
      그 태스크의 집으러·파지 국면만 (8청크)     4등급이상 88% · 3등급이상 100%
      나머지 (363청크)                        4등급이상  1.1%

    E NO_HOLD
      밀기·열기·돌리기 태스크 (69청크)          4등급이상 29.0%
      집어 옮기기 태스크 (311청크)              4등급이상  0.0%

C 는 얹힌 것을 집는 그 순간에 88% 로 켜지고 다른 데서는 1.1% 다. 전체 2.9% 는 그
태스크가 표본의 4.5% 뿐이라 나온 값이다. E 도 같다(해당 태스크가 18%).

**규칙을 이렇게 고친다: "4등급 이상 0~5%" 는 발동이 균일하게 낮을 때만 죽은 문항을
뜻한다. 해당 태스크·국면에 정확히 몰려 있으면 낮은 전체 비율이 정상이다.**

이것은 과거 판정에도 영향이 있다. v2 의 원래 B(CROWDED_PICK)가 3% 로 "죽었다" 고
진단돼 v3b 에서 교체됐는데, 지금 C 가 사실상 같은 비율로 **정확히 겨눠져 있다.**
v2 의 B 도 죽은 것이 아니었을 가능성이 크다(v3b 의 재조준은 국면몫이라는 다른 목표에서
측정으로 이겼으므로 그 결정 자체를 뒤집지는 않는다).

## 계산 사실 -- `scripts/libero_v3d_descriptors.py`

* 속도를 **백분위**로 준다. v3c 는 절대 임계 두 개(`SLOW_POS`=0.2, 0.7)로 세 구간을
  나눴는데 실측 분포가 **3.6% / 50.1% / 46.3%** 로 뭉개져 있었다("barely moving" 이
  사실상 안 쓰인다). robocasa 가 같은 이유로 백분위로 갈아탄 자리인데 libero 는 그
  업그레이드를 못 받았다. 표: `configs/libero_speed_percentiles.json`
  (120에피 · stride 16 · 1,102 표본 · 101 경계). 표가 없으면 **죽는다** -- 조용히 옛
  문구로 강등되면 어떤 문구로 만든 라벨인지 알 수 없다.
* `(mean step 0.34, peak 0.74)` 를 뺐다. 단위가 없어 0.34 가 무엇인지 알 수 없고
  백분위 문구가 같은 뜻을 이미 전달한다.

## 남은 것

가중은 잠정이다. v3c 값은 교체되기 전 v2 성질이 덮는 태스크 수로 유도된 것이라 새
문항에는 근거가 없다. 라벨링 뒤 실측 적합(R5). A 는 전 국면 2.99~3.18 로 사실상
상수인데(목적지 성질이라 에피 안에서 안 변한다) 태스크 간 보정을 맡는 자리다 --
human_data 의 B 와 같은 역할이다.
