# LIBERO 압축 유지율 — 정본

## 두 가지를 조심한다

**1. clip 을 켜고 잰 런은 쓰지 않는다.** 같은 설정에서 유지율이 0.587 대 0.990 으로
갈린다. 하네스 제약을 데이터의 성질로 읽게 된다.

```
output/libero/baseline_*, released_*   clip 켬  -- 쓰지 않는다
taekwan 쪽 *_clipoff_* 런              clip 품  -- 이것이 정본
```

**2. 런 이름의 K 가 배속이 아니다.** `eqs_compress_scope: replan` 이면 재예측 창을
K 로 쪼개고 꼬리가 낱개로 남는다. 실제 배속 = 창 길이 / 행 수.
`analysis/eval_results/libero_ladder_noclip.md` 에 먼저 적혀 있던 함정이다.

**실제 배속은 스텝 수로 재야 하고, 양쪽 다 성공한 에피소드로 짝지어야 한다.**
성공한 에피만 각자 평균 내면 편향된다 -- 압축판이 어려운(긴) 에피에서 실패하면
남은 성공 집합이 짧은 쪽으로 쏠려 배속이 부풀려진다. 실제로 그렇게 재면 사다리가
단조롭지 않게 나온다(1.62 배가 1.76 배보다 유지율이 낮음).

## 사다리 (clip 품, b32, 40 태스크 x 50 에피)

| 실제 배속 | 유지율 | 런 | 이름이 말하는 K |
|---:|---:|---|---|
| 1.00 | 1.000 | `Data/libero_all_Fine` | K=1 (all-fine) |
| **1.53** | **0.990** | `Data/libnaive_clipoff_s7_K2_allk2` | "K2" |
| ~1.76 | 0.810 | `analysis/libero_retention/K2p5_clipoff.csv` | "2.5배" |
| **1.80** | **0.621** | `Isaac-GR00T/output/libero/libnaive_clipoff_s7_K4_allk2` | "K4" |

1.53 배는 사실상 공짜이고 **1.53 과 1.80 사이에 절벽이 있다.**

robocasa 와 견주면 **LIBERO 가 압축에 약하다** -- robocasa 는 2.0 배에서 0.916 인데
LIBERO 는 1.8 배에서 이미 0.621 이다.

## suite 별 (이름 기준 K2 / 2.5 / K4)

| suite | 1.53배 | ~1.76배 | 1.80배 |
|---|---:|---:|---:|
| `libero_object` | 1.004 | 0.966 | 0.837 |
| `libero_goal` | 0.998 | 0.811 | 0.627 |
| `libero_10` | 1.002 | 0.772 | 0.603 |
| `libero_spatial` | 0.955 | 0.690 | **0.416** |

1.53 배에서는 넷이 0.955~1.004 로 구별이 안 되고, 그 위부터 갈린다.
**문항 채점은 갈리는 구간을 써야 한다** -- 1.76 배 판이 갈림길에 가장 가깝다.

## 문항 채점에 쓸 때

태스크별 국면 구성은 유지율을 설명하지 못한다(전부 p>0.17, 기준성공 교란 없음
+0.141 p=0.385). robocasa 와 같다 -- 태스크 수준 목표에는 계산으로 잡히는 구조가
없으므로 **태스크 유지율은 부호 확인용**이고 주 채점은 국면 지표로 한다
(`docs/QUESTION_DESIGN_HARNESS.md` R1).

재현: `python scripts/libero_retention.py`
