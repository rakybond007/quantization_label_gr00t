# 새 allex 데이터셋 (frontier_demo_cumul) 계산 사실 계층 점검

## 데이터셋

| | v1_v2_v3_v4_v5_v6 | v1_v2_v3_v4 |
|---|---|---|
| 에피 | 480 | 320 |
| 프레임 | 1,059,641 | 771,862 |

**320판은 480판의 앞 320 에피와 동일하다** (length·episode_origin 320/320 일치).
480판만 라벨링하면 320판은 `episode_index < 320` 슬라이스로 얻는다.

출처는 `frontier_demo v1~v6 / allex / train_no_subtask_256x256` 각 80에피.
이름대로 **서브태스크 주석이 없다** -- 옛 allex 의 `meta/subtasks.jsonl` 과
parquet 의 `hojin` 열이 여기엔 없다. 국면은 액션에서 유도해야 한다.

액션 규격은 옛 allex 와 **관절 이름까지 같다**(48차원: 팔 14 · 손가락 30 · 목 2 ·
허리 2). 뷰는 ego 좌/우 2개 256x256, 30fps. 그래서 `descriptors` 와 `facts_v3` 가
고치지 않고 그대로 돈다(실행 확인).

## 임계값: 그대로 써도 된다

표본 3,960개(6판에서 6에피씩, 프레임 stride 20):

| 특징 | 임계 분위 | 세 칸 비율 |
|---|---|---|
| gap_mean | 56.5% / 77.2% | 56.5 / 20.7 / 22.8 |
| arm_speed | 28.2% / 67.0% | 28.2 / 38.8 / 33.0 |
| hand_change | 44.1% / 63.0% | 44.1 / 19.0 / 37.0 |
| wrist_rot | 42.3% / 64.8% | 42.3 / 22.4 / 35.2 |

빈 칸이 없다. robocasa 에서 속도 임계가 1.6/46.6 분위에 있던 것 같은 문제는 없다.

## MERGE_LIMIT 은 이 녹화본 값으로 바꿔야 한다

`allex_v2_common.py` 주석이 이미 못박아 두었다 -- 이 상수는 녹화본마다 다르고
가져다 쓰면 안 된다(v5 의 0.159 를 v1 에 썼더니 32% 가 오탐이었다).

`allex_v2_calibrate.py` 를 새 데이터셋에 돌린 결과 (30에피 · 67,423 스텝):

```
single-step |dA| rad   p99/p99.5/p99.9/max  [0.211 0.265 0.412]  1.382
```

* 현재 상수 0.385 (옛 v1 녹화본) -> "불가능" 문장이 뜨는 비율 4.62%
* 이 녹화본 값 0.412               -> 4.02%

차이는 작다. 32% 참사 같은 상황은 아니다. 그래도 문장이 "이 로봇이 데모에서 넘은
적 없는 값" 이라고 **주장**하므로 이 녹화본에서 잰 값을 써야 맞다.

    ALLEX_MERGE_LIMIT=0.412

`ROT_ACCUM_LIMIT_V2` 와 `GAP_RATE_LIMIT_V2` 는 v3 프롬프트가 쓰지 않는다(확인).

## 그림에서 본 것

`timeline_ep0.png` (한 에피 88초를 24칸으로) · `variety.png` (여섯 판에서 4칸씩).

택배 분류 스테이션이다. 금속 슈트에 소포가 놓이고 로봇이 컨베이어로 옮긴다.
**한 에피소드에 소포가 10개쯤 지나간다** -- 신호가 주기적으로 진동하는 이유다.

물체가 두 부류로 갈린다.

* **딱딱한 상자** -- 골판지, EMS/우체국 상자. 모양을 유지한다.
* **물렁한 비닐** -- 주황·파랑·분홍 폴리백. 쥐는 자리에 따라 모양이 바뀐다.

옛 allex 의 상자/봉투 구분이 여기서도 살아 있다. 여섯 판(v1~v6) 사이에 눈에 띄는
차이는 없다 -- 같은 스테이션, 같은 물체군이다.

손은 다지 핸드이고 집기보다 **옆에서 감싸거나 밀어 옮기는** 동작이 많다.
두 손이 다 붙는 구간이 34.1% 다(`held`).

## 국면 유도 (`scripts/allex_new_phase.py`)

**손가락으로 가를 수 없다.** 12에피 25,450프레임에서 오른손 굽힘 p90 = 0.079,
왼손 p90 = 0.232 로 사실상 안 움직인다. robocasa 의 그리퍼 개폐, libero 의 그리퍼
차원에 해당하는 신호가 이 로봇엔 없다 -- 편 손으로 감싸거나 밀어 옮긴다.

대신 기존 기술자가 이미 쓰는 **두 손바닥 사이 유지**(`held` = 간격 < 0.42 이면서
한 팔만 쓰는 게 아닐 때)로 가른다. 위험 모델 전체가 그 유지를 잃는 것을 다룬다.

| 국면 | 정의 | 비율 |
|---|---|---|
| 접근 | 안 쥠 · 손바닥이 모이는 중 | 25.7% |
| 감싸기 | 창 안에서 안 쥠 -> 쥠 | 2.7% |
| 정렬 | 쥔 채로 손목 회전 >= 31도 | 1.8% |
| 운반 | 쥔 채로 옮김 | 25.7% |
| 해제 | 창 안에서 쥠 -> 안 쥠 | 2.0% |
| 빈손 | 아무것도 안 쥠 | 42.0% |

여섯 국면이 12에피 중 10~12에피에서 모두 나온다.

### 그림으로 확인한 것 (`phases.png`, 국면마다 4칸)

* **빈손** 은 실제로 빈 슈트다. 맞다.
* **감싸기·운반·해제** 는 소포가 두 손바닥 사이에 있다. 맞다.
* **정렬** 은 소포가 기울거나 돌아가는 장면이다. 맞다.
* **다만 접근과 감싸기가 서로 닮았고, 운반과 해제도 닮았다.** 전이 국면이라
  당연한 면이 있지만, "문항이 국면을 가르는가" 를 볼 때 이 둘씩은 붙어 있다고
  보고 읽어야 한다.

전이 국면(감싸기·정렬·해제)이 2% 안팎이라 국면균등 표본을 뽑을 때 이 셋이
병목이다 -- 에피를 넓게 훑어야 채워진다.
