# libero 문항을 human_data 두 데이터셋에 그대로 쓸 수 있나 — **결과를 보기 전에 적는 예측**

날짜 2026-09-16. 근거는 영상 확인(에피0 3시점 × 2카메라)과 액션/메타 통계뿐.
Gemini 답을 아직 한 건도 보지 않았다.

## 데이터셋

| | pnp_task | long_horizon_task |
|---|---|---|
| 에피 | 101 | 51 |
| 지시문 | 3종 (인형/파란컵/초록큐브 -> **접시**) | 1종 (인형·초록큐브 -> 왼쪽 **빨간컵**, 민트큐브 -> 오른쪽 빨간컵) |

| naive 유지율 | 1x 91.9 · 2x 91.7 · 3x 86.1 · 4x 69.4 | 1x 93.3 · 2x 83.3 · 3x 53.3 |

## 문항별 예측

**A (반듯이 앉혀야 하는 작고 고정된 자리: 접시·화구·선반)**
- pnp: **높게 나온다(4~5)**. 문항이 "plate" 를 예시로 대놓고 든다.
- long: **갈린다**. 컵은 예시에 없고, "받아주는 것" 으로도 "작고 고정된 자리" 로도 읽힌다.
- => A 가 두 데이터셋을 가르지 못하거나, **pnp 를 더 위험하다고 말할 것**이다.

**B (지금 그리퍼가 닫히는 중)** 둘 다 잘 돈다. 국면에 따라 갈릴 것.

**C (받아주는 것 안에 넣기: 바구니·통·사발)**
- pnp: 접시는 받아주지 않는다 -> 낮게.
- long: 컵은 받아준다 -> 높게. 단 좁은 컵이라 "중심에서 벗어나도 무방" 이 사실과 다르다.
- => C 가 **long 을 더 안전하다고 말할 것**이다.

**D (놓는 중/곧 놓음)** 둘 다 잘 돈다.

**E (붙잡을 필요 없는 일: 밀기·손잡이 돌리기·서랍 닫기)**
- **둘 다 전 청크 1등급.** 두 데이터셋에 그런 국면이 하나도 없다. 전부 집어 옮기기다.
- => 죽은 문항. 분산 0 인데 conf 가중은 차지한다.

## 종합 예측 (이게 핵심이다)

A 와 C 를 합치면 libero conf 는 **pnp 를 덜 압축가능, long 을 더 압축가능**이라고
말할 것이다. 그런데 실측은 **반대**다 — pnp 가 3배속 86.1 로 버티고 long 이 53.3 으로
무너진다. 즉 **문항을 그대로 쓰면 두 데이터셋 사이에서 부호가 뒤집힌다.**

원인은 libero 문항이 "받아주는 용기 = 너그럽다" 를 바구니·사발 기준으로 썼는데
long 의 목적지는 **좁고 선 컵**이라 전혀 너그럽지 않다는 것이다.

## 그래서 예상 결론

**그대로는 못 쓴다.** 최소 두 군데를 고쳐야 한다.
1. E 를 빼거나 이 임바디먼트에 있는 국면으로 교체.
2. C 의 "받아주는 것" 을 **입구 넓이**로 다시 쓴다 (넓은 접시·대야 vs 좁은 컵·병).

## 검증 방법

두 데이터셋에서 국면이 다른 청크를 각각 30개씩 뽑아 Gemini(libero 프롬프트)로 돌리고
위 예측과 대조한다. 확인할 것:
- E 의 등급 분산이 0 에 가까운가
- A·C 의 데이터셋별 평균이 위 방향인가
- conf 의 데이터셋 순서가 실측 유지율과 반대인가
