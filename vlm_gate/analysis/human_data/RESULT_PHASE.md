# 국면별 conf — 집을 때·내려놓을 때가 낮은가

**유지율 숫자는 쓰지 않았다.** 실기 eval 이라 압축이 잘 되는 것처럼 보일 수 있고,
거기 맞춰 문항을 깎으면 그 숫자에 과적합된다. 물리적으로 자명한 순서만 본다.

국면은 그리퍼 전이에서 직접 찍는다(비율로 찍으면 안 된다 -- 앞 판에서 0.80 지점이
아직 닫힌 운반 중이었다). 100청크, libero 문항 그대로.

| 국면 | conf | | A | B | C | D | E |
|---|---:|---|---:|---:|---:|---:|---:|
| 1 집으러 내려감 | 0.327 | 낮다 ✓ | 1.05 | **4.85** | 1.05 | 1.05 | 1.05 |
| 2 파지 | 0.339 | 낮다 ✓ | 1.15 | **4.70** | 1.15 | 1.15 | 1.15 |
| 3 운반 | 0.679 | 높다 ✓ | 1.10 | 1.05 | 3.75 | 1.15 | 1.05 |
| **4 내려놓으러** | **0.830** | **높다 ✗** | 1.00 | **1.00** | 4.80 | 3.30 | 1.00 |
| 5 놓고 물러남 | 0.853 | 높다 ✓ | 1.10 | 1.10 | 4.80 | 4.30 | 1.10 |

집기·내려놓기 평균 0.499 vs 운반·물러남 0.766. 방향은 맞지만 **4번 국면 하나가
어긋난다.**

## 무엇이 빠졌나

집는 쪽은 B 가 받는다(4.85 / 4.70). **내려놓는 쪽에 그런 문항이 없다.** 물건을 쥔 채
목표 위로 내려가는 동안 B 는 1.00 이고(그리퍼가 이미 닫혀 있다) 켜지는 것은 C 4.80 ·
D 3.30 으로 전부 안전 쪽이다. 그래서 conf 가 0.830 -- 이미 놓고 물러난 뒤(0.853)와
거의 같다.

**필요한 것은 B 의 거울이다.**

```
B (있음)  지금 물건에 그리퍼가 닫히는 중인가
빠짐      쥔 채로 목표 위에 내려놓는 중인가, 아직 놓지 않았는가
```

덤으로 D 의 `or about to` 가 헐거워서 내려가는 중에도 3.30 으로 켜지며 conf 를 위로
민다. D 는 "이미 놓였고 벌리기만 남았다" 로 좁혀야 한다.

HD_PER_DS=50 python scripts/humandata_gemini_probe.py out.jsonl
