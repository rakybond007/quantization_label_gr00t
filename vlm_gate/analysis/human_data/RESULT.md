# libero 문항을 human_data 두 데이터셋에 그대로 쓸 수 있나 — 결과

예측은 `PREDICTION.md` 에 **돌리기 전에** 적었다. 표본 72청크, Gemini
gemini-3.8-flash(low), $0.18. 국면은 그리퍼 전이로 찍었다(접근·파지·운반·해제).

## 예측 채점 — 6개 중 2개 맞음

| 예측 | 결과 | |
|---|---|---|
| E 죽는다 | 1.06 / 1.11 · 72개 중 66개가 1등급 | 맞음 |
| B 잘 돈다 | 2.86 / 2.97 · sd 1.89 | 맞음 |
| A 가 pnp 에서 높다(목적지가 접시) | 1.06 / 1.11 — 어디서도 안 켜짐 | 틀림 |
| C 가 long 에서 높다(컵이 받아줌) | 2.78 / 2.72 — 두 데이터셋 동일 | 틀림 |
| D 잘 돈다 | 1.92 / 1.92 · 절반 이상 1등급 | 반만 |
| **conf 가 역전된다** | 0.561 vs 0.550 — 역전 아님 | 틀림 |

## 진짜 문제: 역전이 아니라 무감각

```
conf       pnp 0.561   long 0.550    차이 0.011
실측 유지율  pnp 0.937   long 0.571    차이 0.366   (3배속/1배속)
```

3배속에서 한쪽은 94% 살고 한쪽은 57% 로 무너지는데 conf 는 둘을 같다고 말한다.
두 데이터셋을 가르는 것 -- **넓고 평평한 접시 vs 좁고 선 빨간 컵** -- 을 묻는
문항이 없다.

## 문항별 판정

| | 평균 (pnp/long) | 국면 반응 | |
|---|---|---|---|
| A 작고 고정된 자리(접시·화구·선반) | 1.06 / 1.11 | 없음 | 이 데이터셋에선 안 켜짐 |
| B 지금 그리퍼가 닫히는 중 | 2.86 / 2.97 | 파지·해제 3.49 vs 운반 1.06 | 켜짐 |
| C 받아주는 것 안에 넣기 | 2.78 / 2.72 | 운반 3.88 vs 파지·해제 2.40 | 켜짐 |
| D 놓는 중 | 1.92 / 1.92 | 파지·해제 2.15 vs 운반 1.18 | 켜짐(약함) |
| E 붙잡을 필요 없는 일 | 1.06 / 1.11 | 없음 | 이 데이터셋에선 안 켜짐 |

### 안 켜지는 문항은 버릴 이유가 아니다

처음에 "A·E 를 뺀다" 고 썼는데 **틀렸다.** 두 가지 때문이다.

1. **순위를 안 흔든다.** 전 청크가 1등급이면 conf 에 상수가 더해질 뿐이다. 실제로
   빼고 계산해 보면 전체판과 순위상관이 **+0.998** 이다. 달라지는 것은 conf 폭
   (0.291 -> 0.500) 과 평균 위치뿐이고, 그건 τ 를 다시 잡으면 되는 문제다.
2. **애초에 모든 문항이 모든 데이터셋에서 켜지도록 만든 것이 아니다.** 문항은 그
   벤치마크의 **측정된 피해**에서 RISK/SAFE 풀을 만들어 뽑는다(`FORMAT.md` §4).
   libero 의 E 는 libero 에 밀기·손잡이·서랍 태스크가 있어서 나왔다. 그것이 없는
   임바디먼트에서 안 켜지는 것은 정상이다.

## 판정 기준은 하나다

```
conf       pnp 0.561   long 0.550    차이 0.011
실측 유지율  pnp 0.937   long 0.571    차이 0.366
```

**살아 있는 문항들만으로 이 차이를 만들지 못한다.** B·C·D 가 국면에는 반응하는데
두 데이터셋을 가르지는 못한다. 이것이 유일한 실패다.

그리고 그 실패는 **결손**이다. 두 데이터셋의 3배속 유지율이 94% 대 57% 로 갈리는
이유는 목적지가 **넓고 평평한 접시**냐 **좁고 선 컵**이냐인데, 다섯 문항 어디에도
그것을 받는 자리가 없다.

## 해야 할 일

1. **목적지 입구 넓이를 묻는 문항을 넣는다.** 넓은 접시·대야처럼 여유가 있는가,
   좁은 컵·병처럼 입구가 물건만 한가. 이것 하나가 빠진 자리다.
2. A~E 는 그대로 둔다. 해가 없고 다른 벤치마크에서는 쓰인다.
3. 가중과 τ 는 라벨링 뒤에 이 임바디먼트에서 다시 잡는다.

## 전문 쪽에서 바뀐 것

`MEASURED FROM ...` 한 블록뿐이다. GUIDANCE·뷰 문구·지시문 줄·척도·문항은 libero
정본과 글자까지 같다. 계산 사실이 바뀌어야 하는 이유:

- 액션이 `joint_pos_abs`(절대 관절 7 + 연속 그리퍼 1) 라 병합이 델타 합이 아니라
  `max‖a[i+K] - a[i]‖` 다.
- 그리퍼가 연속값이라 이진 가정이 안 맞는다.
- **문턱은 전부 데이터셋 자기 분포에서 낸다** (`humandata_quantiles.py`).
  처음에 속도 3단을 0.004/0.012, 그리퍼를 0.4 로 **내가 지어냈다가** 고쳤다 --
  실제는 pnp 0.0152/0.0251 · 그리퍼 0.70, long 0.0123/0.0200 · 그리퍼 0.38 로
  데이터셋마다 다르다. 내 숫자로는 거의 모든 창이 "moving fast" 로 나갔다.
- 한계 주장은 **하지 않는다.** 압축 요구는 5단 분위대로만 말한다. 사실 문장 97개와
  GUIDANCE·문항 전체를 기계로 훑어 limit/exceed/beyond/maximum/infeasible 이
  하나도 없음을 확인했다.
