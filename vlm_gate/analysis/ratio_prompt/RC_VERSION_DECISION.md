# robocasa 문항 — **v10 으로 확정**

사람이 찍은 국면 정답 380타일 · Gemini 3.8 Flash(low) · 판마다 $1.4~1.6 · 2.6~3.4분.
해제는 그리퍼 상태로 둘로 가른다(쥔채 = place_precise 1.25 · 놓음 = place_open 3.13).

## 일곱 판 비교

| | 여유 | rho | 전체 AUC | **태스크내 AUC** | 무엇을 바꿨나 |
|---|---:|---:|---:|---:|---|
| v8 | 0.000 | -- | 0.500 | 0.500 | v7 문항, 포맷만 정규화 |
| v9 | 0.060 | 1.00 | 0.607 | 0.634 | +F(내려놓는 순간) +D 좁힘 |
| **v10** | **0.088** | 1.00 | **0.718** | **0.815** | **+A 를 순간 문항으로** |
| v11 | 0.016 | 1.00 | 0.666 | 0.755 | GUIDANCE 재작성 |
| v12 | 0.074 | 1.00 | 0.651 | 0.741 | GUIDANCE 에 놓기 문단 |
| v13 | 0.038 | 1.00 | 0.689 | 0.755 | F 문구 다듬기 |
| v14 | 0.085 | 1.00 | 0.700 | 0.760 | +압축 요구 두 문장 |

**v10 이 네 지표 모두에서 최선이다.** v8 은 못 쓴다(AUC 0.500 = 동전던지기).

## 지표에 대하여 -- 여유 하나로 보면 안 된다

처음에 `여유`(국면 순서를 물리적 부호로 재현할 수 있는 최소 간격)만 보고 v11~v13 을
"절반 이하로 손해" 라고 했는데 **과장이었다.** 여유는 가중을 [-1,1] 로 묶어 재므로
**등급이 가운데로 몰린 판이 순서가 똑같이 깨끗해도 작게 나온다**(v14 가 그 예 --
국면 점수가 전부 작은데 여유는 v10 과 거의 같다).

`rho` 는 v9~v14 가 전부 1.00 이다 -- **순서는 다 맞는다.**

**태스크내 AUC 가 결정적 지표다.** 청크 단위로 낮은 상한 국면(파지·해제쥔채)과 높은
국면(접근·운반)에서 하나씩 뽑아 순서가 맞을 확률이고, 태스크마다 따로 내고 평균하므로
태스크 정체성이 설명에 못 끼어든다. 리얼로봇에서 쓴 것과 같은 기준이다.

v10 에서 전체 0.718 < 태스크내 0.815 인 것이 중요하다 -- **태스크 안에서 재면 더 잘
가른다**, 즉 "이 태스크는 쉽다" 를 외운 것이 아니라 국면을 보고 있다.

## v10 이 v8 에서 바꾼 것 셋

1. **F 추가** (쥔 채 내려놓는 순간, 부호 −1). robocasa 실측에서 `place_precise` 가
   1.25 로 전체 최저인데 받는 문항이 없었다. D 는 부호가 +1 이라 "안 올리는 것" 까지가
   한계이고 내리지는 못한다.
2. **D 에서 `or about to` 제거.** 아직 쥔 채 내려가는 중에도 켜졌다.
3. **A 를 순간 문항으로.** `Does this motion NEED the gripper to close...` 는 일의
   목적을 물어 파지하러 가는 동안에도 켜졌다(접근 3.01). `Is the gripper CLOSING ...
   right now` 로 바꾸니 접근 1.10 · 파지 4.00 이 됐다.

## 안 넣기로 한 것

**압축 요구 두 문장**(`at 2x ... / at 3x ...`). allex 와 humandata 에는 있고
robocasa·libero 에는 없다. v14 로 넣어 재보니 태스크내 AUC 0.815 -> 0.760 이라 손해고,
libero 266,721청크가 이미 그 문장 없이 만들어져 있다. 사용자 판단으로 **뺀다.**

계산 사실 자체는 네 벤치마크 다 있다 -- 빠지는 것은 배속을 가정한 두 문장뿐이다.
robocasa 는 그리퍼 상태·방향·속도(분포 대비)·하중·감속을 주고 전부 1배속 값이다.

## GUIDANCE 는 건드리지 않는다

v11 에서 `matters most / least` 를 "정답표" 로 보고 걷어냈다가 여유 0.088 -> 0.016,
태스크내 AUC 0.815 -> 0.755 로 떨어졌다. **그 문장이 C 를 갈라 주고 있었다.**

SYSTEM 이 나빴던 이유는 "판단 방법을 알려줘서" 가 아니라 (1) 답 형식이 모순됐고
(2) 매핑이 틀렸기 때문이다. robocasa GUIDANCE 는 둘 다 해당 없다. allex 와 libero
GUIDANCE 도 똑같이 무엇이 위험한지 말한다 -- 그게 GUIDANCE 가 하는 일이다.
