# 판정기를 바꿔 보면 -- Cosmos3-Nano · Claude Opus · Claude Sonnet

**파이프라인은 그대로 두고 판정기만 바꾼다.** 같은 그림, 같은 계산 사실, 같은
GUIDANCE 와 문항(allex v4c, A~D 4문항), 같은 conf 식. 차이는 모델 탓이다.

대상: allex `frontier_demo_cumul/v1_v2_v3_v4` ep52 의 12청크(stride 144).

## 입력을 맞추는 것이 먼저다

처음에는 프런티어 모델에게 **12청크를 한 격자로** 주었다. 그러면 앞뒤 청크가
같이 보여서 유리하다 -- Cosmos 는 청크 하나를 좌우 두 뷰로만 받는다.

같은 12청크를 **청크별 좌우 두 뷰**로 다시 주자 **12개 중 10개의 답이 바뀌었다.**
맥락 이점은 실재했다. 아래 수치는 조건을 맞춘 뒤의 것이다.

    opus 격자판   sd 0.225 · 2x요구 상관 -0.305
    opus 청크별   sd 0.204 · 2x요구 상관 -0.293   (둘 사이 상관 +0.917)

## 계산 사실을 이 목적에 맞게 다시 썼다

기존 문구("팔이 보통 속도로 움직인다")는 판정기가 등급으로 옮기기 어렵다.
압축이 무엇을 요구하는지를 **결론까지 계산해서** 준다:

    running this at 2x would ask 0.448 rad in one step, BEYOND anything in the
    demonstrations; at 3x it would ask 0.586 rad, BEYOND anything ...

시연 한계는 이 녹화본에서 보정한 0.385 rad 이다(`MERGE_LIMIT_V2`).

## 가중은 판정기마다 따로 잡아야 한다

처음에 세 판정기를 **Cosmos 라벨에 맞춰 잡은 가중**(A .80 · B .20 · C .30 ·
D .70)으로 다 쟀다. 그러면 Cosmos 에게만 유리하다. 실제로 그 가중에서
Sonnet 의 순위상관은 +0.50 이었는데, **Sonnet 라벨로 다시 적합하니 +1.00** 이
됐다. 문항 문구와 부호는 그대로이고 가중만 바뀐다(하네스 R5: 가중은 라벨 뒤에
정한다 -- 판정기가 바뀌면 라벨이 바뀌므로 가중도 다시 잡아야 한다).

같은 64청크 · 같은 정답지(눈으로 표시한 세 범주) · 각자 자기 가중:

| 판정기 | 가중 A/B/C/D | ρ | 양손 | 봉투 | 상자 | 간격 | conf sd |
|---|---|---|---|---|---|---|---|
| Cosmos3-Nano | .95 / .05 / 0 / 1.0 | +1.00 | 0.552 | 0.680 | 0.689 | 0.138 | 0.125 |
| **Sonnet 4.5** | .65 / .35 / 0 / 1.0 | **+1.00** | 0.193 | 0.429 | 0.433 | **0.240** | **0.224** |

순서는 둘 다 맞는다. 다른 것은 **벌어진 정도**다 -- Sonnet 이 간격 1.7배 ·
변별폭 1.8배로, 역치를 놓을 여유가 그만큼 크다.

**C(FREE_END)는 세 판정기 모두에서 가중 0 이 된다.** 일관되게 버려지므로 뺀다.

### 문항별로는 서로 다른 것을 잘한다

| | B (봉투) 차 | A (양손 상자) 차 |
|---|---|---|
| Cosmos | **+2.72** | +0.57 |
| Sonnet | +1.47 | **+2.74** |

Cosmos 는 봉투를, Sonnet 은 양손 상자 파지를 잘 본다. 실측 최악이 양손 상자
돌리기(0.533)이므로 그쪽이 더 중요하다.

## 최종 -- 네 범주 정답지 · 76청크 · 각자 자기 가중

정답지는 프레임을 직접 보고 표시했다. 문항마다 표적 범주가 하나씩 있다.

    2 양손상자 18  실측 0.533   A(PINCH_RIGID) 의 표적 -- 실측 최악
    1 한손봉투 24       0.767   B(POUCH)
    0 한손상자 28       0.930
    3 Pass      6       0.98    C(FREE_END)

| 판정기 | A차 | B차 | C차 | ρ | 간격 | conf sd |
|---|---|---|---|---|---|---|
| Cosmos3-Nano | +0.43 | **+2.69** | +0.25 | +1.00 | 0.127 | 0.108 |
| **Sonnet 4.5** | **+2.61** | +1.53 | **+1.61** | +1.00 | **0.390** | **0.210** |
| Gemini 3.8 Flash | +0.47 | +2.01 | +0.48 | +1.00 | 0.211 | 0.169 |

셋 다 순서는 재현한다(ρ +1.00). 다른 것은 **벌어진 정도**와 **어느 문항을
잡느냐**다. Sonnet 만 세 문항 전부 자기 표적을 잡고, 간격이 Cosmos 의 3배다.

**Cosmos 와 Gemini 는 봉투는 잘 보는데 가장 위험한 셀(양손상자)을 못 본다**
(A차 +0.43, +0.47). 그것이 게이트의 핵심이다.

### 정답지 때문에 세 번 틀렸다

이 비교에서 "문항이 안 된다" 고 결론 낼 뻔한 것이 세 번이고, 세 번 다 자가
틀렸다.

| 무엇 | 잘못된 정답지 | 고친 뒤 |
|---|---|---|
| B (봉투) | 화면 **색**으로 봉투를 찾음 -> 배경 봉투를 셈 | +0.35 -> **+1.77** |
| A (양손상자) | 장면을 한손 구간만 뽑아 표적이 아예 없음 | 무용지물 -> **+2.61** |
| C (Pass) | 막판을 **비율로 잘라** 표시 -> 절반이 Pass 가 아님 | +0.28 -> **+1.61** |

**발동한다 != 맞게 발동한다.** Gemini 가 C 에 4등급 이상을 25.4% 주는 것을
보고 "Gemini 만 C 가 살아 있다" 고 읽었는데, 정답지를 붙이니 표적에서 뜬 것이
아니었다. 발동률(하네스 R7)은 죽은 문항을 걸러낼 뿐이고, 맞는지는 정답지가
있어야 안다.

### 가중으로는 못 고치는 것이 있다

A차는 **A 등급 자체가 표적에서 얼마나 뜨느냐**이고, 가중은 문항들을 conf 로
합칠 때의 배분만 바꾼다. Gemini 에 A 가중을 1.0 을 줘도 등급이 2.28 대 1.81
이면 그만큼만 갈린다. **가중으로 고칠 수 있는 것은 순서이고, 분리도는 문구로만
고친다.**

## 알아낸 것

**서브태스크 안에서 상수가 되지 않는다.** 계산 사실이 프롬프트에 들어오므로
같은 국면 안에서도 갈린다 -- #3 과 #4 는 둘 다 "양손이 상자를 맞뭄" 인데
2배속 요구가 0.063 vs 0.225 라 등급이 달라진다.

**문항에 구멍이 있다.** #10 은 2배속 요구가 0.448 로 시연 한계를 넘는데, 네
문항 어디에도 "압축 요구가 로봇의 한계를 넘는가" 를 묻는 자리가 없다. 그래서
conf 가 그만큼 안 내려간다 -- 세 판정기 모두 2x요구와의 상관이 -0.3~-0.43 에
그친다. 계산 사실이 말해 주는데 문항이 받지 못한다.
