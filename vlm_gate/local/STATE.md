# 현재 상황 (2026-08-27 기준)

## 무엇을 하는 연구인가

GR00T-N1.5 VLA 정책의 **행동 청크(16스텝)마다, 이 구간을 절반 속도로 실행해도
되는가**를 판단하는 게이트. 되는 구간만 K2로 압축하면 성공률을 지키면서 스텝을 줄인다.

핵심 결과 하나: OpenDrawer를 82% 압축 → 성공률 0.68 / 성공시 178스텝.
(무압축 0.72 / 229스텝, 무지성 K2 0.44 / 136스텝)
**얼마나 압축하냐보다 어디를 압축하냐가 중요하다**는 증거.

## 4층 구조

1. 임베디먼트 어댑터 (robocasa = EE 델타 합산, allex = 절대 관절 타겟 건너뛰기)
2. 결정론적 계산층 — grip_transition / reversal / precise_hold / infeasible_merge
3. VLM 판단층 — 계산으로 알 수 없는 **장면 정보만**. 계산값은 묻지 않고 **사실로 진술**해준다.
4. 집계·증류 — noisy-OR → 순위정규화(τ = 차단율) → 학생 A' 로 증류

## 측정으로 결론난 것 (다시 뒤집지 말 것)

- 2콜 > 8콜 (AUC 0.830 vs 0.763, 3.6배 빠름)
- 액션 관련 문항은 **묻지 말고 계산**해야 한다 (reversal 물어보면 AUC 0.520 = 무작위)
- 계산값을 질문으로 주면 답이 붕괴한다 → **사실로 진술**할 것
- 스케일 기준 이미지 필수 (그리퍼 검출 70.4% → 36.2%, 있으면 83.9%)
- 가중평균보다 noisy-OR (검출률 4.5% → 71.6%)
- **가이던스만 바꾸는 것으로는 부족하다. 문항도 국면 기준이어야 한다.**
  (OpenDrawer: 가이던스만 0%→0%, 문항까지 바꾸면 0%→67%)
- 학생 A'는 **이미지 + 지시문만** 받는다. 액션을 입력으로 주면 액션 헤드 디노이징과
  동시 실행(MPS)이 불가능해져서 숨겨지던 지연이 순수 오버헤드가 된다.
- 학생의 val AUC가 낮은 건 결함이 아니다. 서로 다른 라벨로 학습된 학생끼리 AUC를
  비교하는 것은 무의미하다 (증류가 깨졌는지 감지하는 용도로만 쓴다).

## 열려 있는 의문

- **D 문항이 0.7%밖에 안 잡힌다.** 손잡이 파지가 실제로 드문 국면일 수도 있지만
  문항을 너무 좁게 써서 놓쳤을 수도 있다. OpenDrawer 계열에서 따로 확인할 것.
- **p_raw 하위 25%가 정확히 0이다.** noisy-OR 포화. 순위정규화가 덮어주지만
  동점 구간의 순서가 임의가 된다. τ를 낮게 잡을 때 문제가 될 수 있다.
- CloseDoubleDoor가 Δ−0.16으로 나빠지는데 이유를 모른다 (그리퍼가 닫히지도 않는 태스크).
- allex의 τ는 정책이 없어서 정할 수 없다. 정성 판단용 라벨 영상까지만 만들어둔 상태.
- 1스텝 디노이징 결과를 학생 입력으로 주는 안 — 미검증.
