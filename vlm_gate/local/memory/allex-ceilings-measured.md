# allex 상한은 이제 실측이다 (2026-09-04)

v2 의 상한은 사람의 사전 판단이었다. eval 이 없어서 그랬다. 이제 서브태스크별로
리플레이 30회씩 재봤다.

|  | 2배 | 2.5배 | 차이 | 풀 |
|---|---|---|---|---|
| Rotate Box | 22/30 | 16/30 | −20.0%p | **위험** |
| Bring PolyBag | 28/30 | 23/30 | −16.7%p | **위험** |
| Bring Box | · | 27/30 | ~0 | 안정 |
| Pass Object | · | ~30/30 | ~0 | 안정 |
| 비접촉 구간 | — | — | (지정) | 안정 |

## 뒤집힌 것

v2 는 **봉투를 너그러운 물체로 읽었다.** Rotate 를 2.0/2.5 로 가르면서 봉투를
위에 뒀고, `BRING_SOFT` 는 문항 D 가 "무른 비닐봉투"라고 하면 Bring 의 상한을
2.0 에서 2.5 로 **올렸다.** 측정은 정반대다 — 봉투를 옮기는 구간이 가장 먼저
깨진다.

봉투는 **놓기에 너그럽고 옮기기에 까다롭다.** 떨어뜨려도 안 넘어지지만 팔이
빨라지면 출렁이고 미끄러진다. v2 는 이 둘을 한 숫자에 뭉갰다.

그래서 **VLM 이 봉투라고 답한 Bring 청크는 상한이 0.5 높게 붙었다.** 에피소드를
잃는 방향이다. 이미 parquet 에 들어간 라벨이 그렇다.

## 상한값

후보는 {1, 1.5, 2, 2.5, 3} 이고 **4배는 없다.**

| 문항 | 국면 | 상한 |
|---|---|---|
| A | 두 손바닥 맞눌림 (Rotate Box) | 1.5 |
| B | 늘어지는 물체 운반 (Bring PolyBag) | 2.0 |
| C | 옆으로 보냄 (Pass Box) | 3.0 (약한 허용) |
| D | 비접촉 | 2.5 |
| E | 감싸 쥔 이송 (Bring Box) | 3.0 (약한 허용) |

**두 변이 대칭이 아니다.** 그냥 가중평균을 쓰면 상한이 상한 노릇을 못 한다.
손에 감싸인 봉투는 B(늘어진다)와 E(손가락이 감쌌다)에 다 걸리는데, 2.0 과 3.0 을
평균하면 2.33 이 나와 **실측 2.0 보다 위로 올라간다** — E 의 3.0 은 박스에서 온
값이기 때문이다. 상한은 의견의 평균이 아니라 **가장 제한적인 근거가 마지막 말을
갖는 것**이다.

    허용 문항(C·D·E)  기준 2.0 에서 얼마나 위로 갈지를 정한다.
                      가장 확실한 하나만큼만 간다 → 희미하면 2.0 근처.
    제한 문항(A·B)    남은 값을 덜 제한적인 것부터 차례로 잘라 내린다.
                      먼저 걸린 허용 문항이 이걸 되돌릴 수 없다.

아무 문항도 안 걸리면 2.0 이다. 손이 비었다고 말하는 건 D 인데, D 가 안 걸렸으면
비었다고 가정할 수 없다.

Rotate Box 는 등급 5→1.50, 4→1.63, 3→1.75, 2→1.88 로 **항상 1.5~2.0 안**이다.

동점은 아래로 내린다. 1.75 는 두 후보 사이 정확히 가운데인데, 한 칸 덜 압축하는
건 잃는 게 없고 한 칸 더 압축하면 에피소드를 잃는다.

## 등급표에서 저지른 것 넷

초안이 규칙 넷을 어겼다. 파일 안에도 적어뒀다.

1. **묻는 것과 다른 걸 등급으로 셌다.** A 는 "두 손바닥이 붙들고 있나"를 묻고는
   5 와 4 를 **돌기 시작했는가**로 갈랐다. 이제 다섯 등급 전부 한 가지다 —
   물체 무게를 그 눌림이 얼마나 받고 있는가.
2. **등급에 움직임을 넣었다.** "출렁인다", "옮겨지고 있다", "밀기 시작했다" 는
   전부 액션에서 나오고 이미 사실로 준다. 숫자로 끝난 걸 다시 물으면 답만 나빠진다.
3. **손이 안 닿았는데도 걸리는 등급을 뒀다.** "무르게 생겼는데 아직 손이 안 갔다"
   같은 것. 배경에 봉투가 굴러다니면 단단한 박스 청크의 배속이 깎이고, 옆에 트인
   상판이 있으면 조심스러운 놓기가 올라간다. 이제 1 을 뺀 모든 등급이 손이 그것에
   닿아 있을 것을 요구한다.
4. **결론을 물었다.** C 가 "몇 cm 어긋나도 괜찮은가"를 물었다. 그게 바로 상한이다.
   지금은 반대편 끝에 무엇이 있는지를 묻는다 — 트인 상판인지, 맞춰 넣을 자리인지.

## 못 재는 것

**eval 루프가 없다. 실제 로봇이다.** 상한은 운용자가 주는 값이지 필요할 때마다
다시 잴 수 있는 게 아니다. Rotate PolyBag 은 리플레이가 없어서 어떤 문항도
이걸 주장하지 않는다.
문항은 `vlm_gate/scripts/allex_v3_checks.py`. 절차는 robocasa 와 같다
(`PROMPT_METHOD.md`). [[harness-limits-not-labels]] 와 마찬가지로 상한은
측정에서 오고 인상에서 오지 않는다.
